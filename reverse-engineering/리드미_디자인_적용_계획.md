# 리드미 디자인 적용 계획 — shadcn/ui와 dsui 섞어 쓰기

2026-11-12 기준. 디자인을 가져오는 방법은 C(shadcn/ui를 기본으로 두고 필요한 부품만 dsui에서 가져오기)로 정했다. 프로젝트 폴더는 `C:\Dev\readme`다. 분석 내용은 `claude/리드미_리서치_디자인_devs7udio.md`에 있다.

이 문서는 설치 순서와 충돌 정리다. 실제 설치는 해 보지 않았다. 근거는 dsui 레지스트리 항목과 문서, shadcn/ui 문서, 그리고 Tailwind v4와 Arc를 함께 쓰고 있는 devs7ud.io에서 관찰한 값이다.

## 1. 요약

- 설치는 shadcn CLI 하나로 한다. `components.json`에 dsui 주소를 등록하고 `add @devs7udio/<이름>`으로 받는다.
- dsui 컴포넌트는 어느 것을 받아도 기반 묶음 전체가 따라온다. 변수 파일, 효과음 11개, 아이콘 묶음, 일러스트 컴포넌트, 슬라이더, 스위치가 함께 설치된다.
- 부딪히는 곳은 열 군데다(5절). 그중 설치 전에 정해야 하는 것은 셋이다: 버튼을 어느 쪽 것으로 쓸지, 포커스 표시를 어느 쪽 것으로 쓸지, 다크 모드를 처음부터 넣을지.

## 2. 어느 쪽에서 무엇을 가져오나

"폼과 표는 shadcn/ui, 골격과 표현은 dsui"를 기준으로 잡았다. 항목별 확정은 아직이다.

| 쪽 | 맡는 것 | 항목 |
|---|---|---|
| shadcn/ui | 입력, 선택, 겹쳐 뜨는 창, 표 | input, textarea, select, checkbox, dialog, dropdown-menu, popover, table, toast 등 |
| dsui | 헤더, 선택 전환, 표시용 부품 | 아래 후보 목록 |

dsui 레지스트리에서 리드미 화면에 쓸 만한 항목:

| 용도 | 항목 이름 |
|---|---|
| 헤더와 메뉴 | `app-header`, `mobile-nav-sheet`, `user-menu`, `command-palette` |
| 선택 전환과 필터 | `segmented-control`, `tabs`, `icon-tabs`, `chip`, `chip-group`, `filter-toolbar` |
| 카드와 지표 | `card`, `item-card`, `metric-card`, `expandable-card`, `usage-meter`, `progress`, `stepper`, `timeline` |

- 헤더는 `site-header`가 아니라 `app-header`가 devs7ud.io의 떠 있는 바에 해당한다. 스크롤하면 떠오르고 내려갈 때 숨는 동작이 들어 있고(`hideOnScroll` 기본값 true), Next.js 없이 동작한다. `site-header`는 `next/image`를 한 군데 써서 Vite에서는 고쳐야 한다.
- dsui에는 입력·선택·표(`input`, `select`, `sortable-data-table`)와 로그인 화면(`sign-in`, `login-centered`, `signup-form`)도 있다. 선을 어디에 그을지는 바꿀 수 있다.
- devs7ud.io에는 있지만 레지스트리에서 찾지 못한 것: 모바일 하단 독, 홈의 톤 카드와 랭킹 행. 쓰려면 분석 문서의 수치로 직접 만든다.

## 4. 설치 순서

프런트 폴더 위치는 저장소 구조가 정해져야 한다. 아래에서는 `<프런트>`로 적는다.

1. **프로젝트 만들기.** `<프런트>`의 상위 폴더에서 `npx shadcn@latest init -t vite`를 실행한다. Vite + React + TypeScript 프로젝트와 Tailwind, `components.json`이 한 번에 만들어진다. 스타일·색·글꼴·아이콘을 고르는 프리셋을 먼저 만들었다면 `npx shadcn@latest init --preset <코드> --template vite`를 쓴다.
2. **shadcn/ui 부품 받기.** 첫 화면(로그인, 경험카드)에 필요한 것부터 `npx shadcn@latest add input select dialog`처럼 받는다.
3. **dsui 주소 등록.** `components.json`에 다음을 넣는다.
   ```json
   { "registries": { "@devs7udio": "https://dsui.vercel.app/r/{name}.json" } }
   ```
4. **받기 전에 내용 보기.** `npx shadcn@latest view @devs7udio/segmented-control`로 어떤 파일이 오는지 확인한다.
5. **기반 묶음만 먼저 받기.** `npx shadcn@latest add @devs7udio/arc-foundation`을 실행하고, 파일이 `src/components/arc/` 아래에 놓였는지 본다.
6. **전역 CSS 고치기.** 6절의 골격대로 `foundation.css`를 맨 위에서 불러오고, shadcn이 만든 색 변수와 연결 블록을 고친다.
7. **dsui 부품 받기.** `npx shadcn@latest add @devs7udio/segmented-control @devs7udio/app-header`처럼 받는다. 이때 3절의 나머지 기반 항목이 들어온다.
8. **기본값 바꾸기.** 효과음 끄기, Pretendard 불러오기, `<html class="light">`, `ArcProvider`에 React Router의 링크 넘기기, 헤더에 리드미 `brand` 넘기기(5절).
9. **나란히 놓고 보기.** 한 화면에 shadcn/ui 버튼·입력·다이얼로그와 dsui 버튼·세그먼트를 함께 놓고 7절 항목을 확인한다.

단계마다 커밋해 두면 CLI가 무엇을 추가했는지 구분할 수 있다.

## 5. 충돌과 해결

| # | 부딪히는 곳 | 그대로 두면 | 해결 |
|---|---|---|---|
| 1 | 변수 이름 다섯 개가 겹친다: `--background`, `--foreground`, `--border`, `--accent`, `--accent-foreground` | shadcn이 만든 `:root`가 뒤에 오므로 그 값이 이긴다. dsui 기본 버튼이 파랑 대신 shadcn의 옅은 회색으로 칠해진다 | 변수는 Arc 뜻으로 하나만 둔다. shadcn이 만든 다섯 줄을 지우고, shadcn 부품이 쓰는 `accent` 색은 연결 블록에서 `--surface-muted`로 돌린다(6절). shadcn 부품은 Tailwind 색 이름으로 읽기 때문에 부품 코드는 고칠 필요가 없다 |
| 2 | `--text-xl`~`--text-5xl`, `--ease-in-out`을 Tailwind와 Arc가 둘 다 정의한다 | Arc 값이 이긴다. Tailwind의 `text-xl`은 20px이 아니라 22px, `text-2xl`은 28px, `text-3xl`은 36px, `text-4xl`은 52px, `text-5xl`은 72px이 된다. lg 이하는 값이 같다 | Arc 크기 단계를 그대로 받아들인다. Tailwind 값으로 되돌리면 Arc 부품의 제목 크기가 줄어든다 |
| 3 | 다크 모드를 고르는 방식이 다르다. Arc는 `<html>`에 `light`·`dark` 표시가 없으면 OS 설정을 따르고, shadcn은 `.dark` 클래스가 있을 때만 바뀐다 | OS가 다크인 사용자에게 Arc 변수는 다크 값이 되는데, shadcn 부품 안의 `dark:` 유틸리티는 켜지지 않는다 | 다크 모드를 만들기 전에는 `<html class="light">`로 고정한다. 만들 때는 테마 전환 코드가 항상 `light`나 `dark` 클래스를 붙이게 한다 |
| 4 | 포커스 표시가 둘이다. `foundation.css`는 전역 외곽선 2px을 `!important`로 건다. shadcn 부품은 자체 포커스 링을 쓴다 | shadcn 버튼 등에 외곽선과 링이 함께 보일 수 있다. 입력창과 메뉴 항목은 Arc 규칙에서 빠져 있어 링만 보인다 | 하나를 고른다. Arc 외곽선으로 통일하면 shadcn 부품에서 링 클래스를 뺀다. shadcn 링으로 통일하면 `foundation.css`의 포커스 규칙 두 개를 지운다 |
| 5 | 버튼이 둘이다. shadcn 다이얼로그 등은 shadcn 버튼을 불러 쓴다. dsui 버튼은 변형 이름이 다르고(`primary`, `secondary`, `ghost`, `accent`, `danger`) `asChild`가 없어 그대로 바꿔 끼울 수 없다 | 화면에 모양이 다른 버튼 두 종류가 섞인다. dsui 버튼은 알약에 높이 36·44·50px이다 | 둘 중 하나. (가) shadcn 버튼만 쓰고 클래스를 고쳐 알약과 높이를 맞춘다. dsui 버튼은 받지 않는다. (나) 둘 다 두고, shadcn 버튼은 shadcn 부품 안에서만 쓰며 모양을 맞춘다 |
| 6 | 모서리 기준이 다르다. shadcn은 `--radius` 하나(기본 0.625rem)에서 단계를 만들고, Arc는 18·26·34px과 알약이다 | shadcn 입력창·카드의 모서리가 dsui 부품보다 작다 | `--radius`를 키워 눈으로 맞춘다. 알약이 필요한 shadcn 부품은 클래스를 고친다 |
| 7 | 효과음이 기본으로 켜져 있다(`enabled: true`, 음량 0.5). dsui 버튼은 누를 때, 세그먼트는 값이 바뀔 때 소리를 낸다. 세그먼트에는 끄는 속성이 없다 | 사용자가 처음 클릭한 뒤부터 소리가 난다 | `components/arc/sound/settings.ts`의 기본값을 `enabled: false`로 고치거나 앱 시작 때 `setSoundEnabled(false)`를 부른다. 버튼 하나만 끄려면 `silent` 속성을 쓴다 |
| 8 | 헤더의 기본 로고가 devs7udio 것이다 | `brand`를 안 넘기면 devs7udio 로고가 나온다 | `app-header`에 `brand`(이름, 주소, 로고)를 항상 넘긴다. `lib/brand-*.tsx`의 로고는 쓰지 않는다 |
| 9 | 아이콘이 두 벌이다. shadcn은 lucide, dsui는 Hugeicons다 | 선 굵기와 모양이 다른 아이콘이 섞인다 | 받아들이거나, shadcn 프리셋에서 아이콘 묶음을 고를 때 맞춘다. Hugeicons를 고를 수 있는지는 확인하지 못했다 |
| 10 | 글꼴 파일이 레지스트리에 없다. Arc 변수는 Pretendard Variable을 가리키고, shadcn 부품은 Tailwind의 `--font-sans`를 쓴다 | Pretendard가 없으면 시스템 글꼴로 나오고, 두 쪽 글꼴이 다를 수 있다 | Pretendard를 직접 불러오고(SIL OFL), 연결 블록에서 `--font-sans`를 `var(--font-body)`로 둔다 |

부딪히지 않는 것: 파일 위치(shadcn은 `components/ui/`, dsui는 `components/arc/`), 모션 패키지(shadcn은 `tw-animate-css`, dsui는 `motion`), 모서리·그림자·간격 변수 이름(서로 다른 이름을 쓴다). Tailwind의 기본 초기화 스타일과 Arc가 함께 도는 것은 devs7ud.io가 그렇게 운영 중이다.

## 6. 전역 CSS 골격

shadcn이 만든 전역 CSS에서 바꾸는 부분만 적었다. 나머지 줄은 그대로 둔다.

```css
/* 1. Arc 기본값을 맨 위에서 불러온다. 경로는 파일 위치에 맞춘다 */
@import "../components/arc/foundation.css";
@import "tailwindcss";
/* shadcn init이 넣은 나머지 @import와 dark 변형 줄은 그대로 */

/* 2. 리드미 값. Arc 변수 이름으로 덮어쓴다 */
:root {
  --accent: /* 리드미 강조색 */;
  --accent-foreground: /* 강조색 위 글자 */;
  --radius: /* shadcn 쪽 모서리 기준 */;
}
:root.dark {
  --accent: /* 다크 강조색 */;
  --accent-foreground: /* 다크에서 강조색 위 글자 */;
}

/* 3. shadcn 색 이름을 Arc 변수에 연결한다 */
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--surface);
  --color-card-foreground: var(--foreground);
  --color-popover: var(--surface-raised);
  --color-popover-foreground: var(--foreground);
  --color-primary: var(--accent);
  --color-primary-foreground: var(--accent-foreground);
  --color-secondary: var(--surface-muted);
  --color-secondary-foreground: var(--foreground);
  --color-muted: var(--surface-muted);
  --color-muted-foreground: var(--text-secondary);
  --color-accent: var(--surface-muted);
  --color-accent-foreground: var(--foreground);
  --color-destructive: var(--danger);
  --color-border: var(--border);
  --color-input: var(--border-strong);
  --color-ring: var(--accent);
  --font-sans: var(--font-body);
}
```

shadcn이 `:root`와 `.dark`에 만든 색 변수 줄은 지운다. Arc에 대응이 없는 것(사이드바 색, 차트 5번)만 남긴다. `@theme inline`의 모서리 줄은 그대로 둔다.

## 7. 설치 뒤 확인할 것

- dsui 파일이 `src/components/arc/`에 놓였는지, 프로젝트 루트의 `components/arc/`에 놓였는지.
- shadcn 버튼과 dsui 버튼을 나란히 놓았을 때 높이, 모서리, 글자 굵기.
- 키보드로 이동할 때 포커스 표시가 하나만 보이는지.
- OS를 다크 모드로 바꿨을 때 화면이 섞여 보이지 않는지.
- 클릭해도 소리가 나지 않는지.
- 헤더에 리드미 이름과 로고가 나오는지.
- dsui 부품에 Tailwind 클래스를 넘겼을 때 적용되는지. 부품의 모듈 CSS가 정한 속성은 유틸리티 클래스로 덮이지 않을 수 있다.
- React Router 링크가 헤더 메뉴에서 새로고침 없이 이동하는지.

## 9. 확인하지 못한 것

- 실제 설치를 해 보지 않았다. 5절의 "그대로 두면"은 CSS 규칙과 문서에서 추론한 것이고, 2번만 devs7ud.io에서 관찰했다.
- 레지스트리 항목은 페이지 요약 도구로 읽었다. 색인에서 읽힌 수(컴포넌트 129, 블록 41, 기반 3, 테마 5)는 dsui 설치 문서의 133개와 다르다. 설치 문서는 예전 devs7udio 항목 일부가 설치되지 않는다고 적는다.
- `app-header`가 불러 쓰는 `lib/` 파일이 선언된 의존 항목만으로 모두 들어오는지 확인하지 못했다.
- shadcn/ui 부품의 실제 클래스(높이, 모서리, 링)는 고르는 스타일에 따라 다르다. 설치 뒤에 본다.
