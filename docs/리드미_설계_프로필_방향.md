# 리드미 방향: 기본 프로필

2026-11-15 기준. 설계 전 방향 정리다. 테이블과 API는 2026-11-16에 `docs/리드미_설계_프로필.md`로 설계해 서버에 넣었다. 가입 값(생년월일·성별)과 동의도 같은 날 서버에 넣었다(로그인 문서 4.1).

**뺐다(2026-11-17, 사용자 결정)**: 가입·구글에서 생년월일·성별과 동의를 받는 것, 성별 칸, 구글 People API를 모두 뺐다. 생년월일은 기본 프로필의 선택 칸으로만 둔다. 프로필은 이력서 관리로 본다(다른 구직 사이트도 가입에서 받지 않는다). 아래의 통계(나이·성별)·생일 이벤트와 구글 민감 범위 검토 이야기는 그 결정 전의 기록이다.

- 경험카드와 추출: `docs/리드미_설계_경험카드.md`
- 계정 테이블과 구글 로그인: `docs/리드미_설계_로그인.md`
- 칸 확인 화면의 모양(근거, 못 읽은 칸은 노란색): `docs/리드미_화면_API_대응.md` 2.4절
- 남은 작업에서의 순서: `docs/리드미_남은작업.md` 3~5단계

## 1. 무엇인가

사람마다 기본 칸 묶음(프로필)을 하나 둔다. 손으로 다 넣어도 되고, 이력서나 포트폴리오를 올리면 서버가 칸을 채운다. 읽지 못한 칸은 사용자가 넣는다. 공고 올리기의 칸 확인과 같은 흐름이다. 참고한 곳: 그룹바이(이력서를 올리면 프로필 초안을 채워 준다).

경험카드와는 다른 기능이다. 프로필은 사람당 하나, 카드는 여러 장이다. 자료를 올리면 한 번의 추출로 프로필 칸과 카드를 함께 뽑는다.

## 2. 정한 것

| 항목 | 정한 값 | 이유 |
|---|---|---|

| 카드와의 관계 | 기능은 분리. 추출은 한 번에 프로필과 카드를 함께 뽑는다 | 사용자는 자료를 한 번만 올리고, LLM 호출이 준다 |

| 이메일 | 계정 이메일(인증된 것)을 쓴다. 이력서에서 읽은 이메일은 쓰지 않는다 | 인증을 거친 값만 둔다 |
| 연차 | 따로 받지 않고 경력 칸(회사·기간)에서 계산한다 | 주니어·시니어 통계 |

| 개인정보처리방침 | 작성한다 | |
| 가입 흐름 | 구글 로그인을 앞에 두어 유도한다. 가입 뒤에 정보를 더 묻는 화면은 두지 않는다 | 화면을 한 번 더 거치면 사용감이 나쁘다 |

## 3. 걸린 것

1. **구글 검토.** `user.birthday.read`, `user.gender.read`는 구글의 민감 범위 검토 대상으로 본다(정확한 분류는 구글 콘솔에서 확인). 검토는 보통 영업일 3~5일, 권한을 받고 쓰는 과정을 보여 주는 영상이 필요하다. 검토 신청에는 앱 홈페이지, 공개된 개인정보처리방침 주소, 확인된 도메인이 필요하다(신청할 때 콘솔에서 확인). 도메인은 아직 정하지 않았으므로 도메인 → 처리방침 게시 → 검토 순서가 출시 일정에 들어간다. 검토 전에는 테스트 사용자로 등록한 계정만 이 범위를 쓸 수 있다.
2. **구글 동의 화면.** 생일·성별 읽기 권한이 늘어난다. 우리 화면은 늘지 않는다. 구글은 두 권한을 따로 체크하게 하므로 사람이 빼고 가입할 수 있다. 서버는 허락한 것만 읽는다(2026-11-16, 로그인 문서 4.1).
3. **값이 빈 사람.** 구글에 생일·성별이 없거나 이메일 가입에서 비운 사람이다. 추가 화면을 두지 않으므로 프로필 칸에서 채운다. 이 사람은 통계와 생일 이벤트에서 빠질 수 있다.
4. **가입 값과 프로필 값.** **뺐다(2026-11-17)**: 가입은 프로필에 아무것도 넣지 않는다. 아래는 2026-11-16의 기록이다. 가입에서 받은 생년월일·성별을 프로필 칸에 넣는다. "빈 칸만 채운다" 규칙대로, 이후 구글 로그인 때 다시 덮어쓰지 않는다. 2026-11-16에 만들었다. 인증 전 계정에 다시 가입하면(남이 먼저 가입만 해 둔 경우) 앞 사람의 값을 이번 값으로 바꾼다(로그인 문서 4.1).
5. **본문에서 가릴 것.** 받지 않는 값도 이력서 원문에 있으면 본문 저장(`card_sources.body`)과 LLM 호출로 넘어간다. 본문을 읽은 직후, 저장·LLM 호출 전에 주민번호 꼴(6자리-7자리)과 전화번호 꼴을 가린다. 2026-11-16에 만들었다. 가리는 꼴과 못 가리는 것은 경험카드 문서 4.4에 있다.
6. **한 번에 뽑기.** (2026-11-16 서버에 들어갔다. 경험카드 문서 4.6) jobfit의 추출 프롬프트는 카드만 뽑는다. 프로필 칸을 더한 출력 모양과 프롬프트를 새로 정해야 한다. 자료를 여러 조각으로 나눠 부르면 프로필 칸은 조각마다 나올 수 있으므로 합치는 규칙(먼저 나온 값, 빈 칸만)이 필요하다. 추출 결과 화면은 카드 확인과 프로필 칸 확인을 함께 보여 준다.
7. **동의.** **뺐다(2026-11-17)**: 가입의 동의 둘과 `V8`의 시각 칸은 `V11`이 지웠다. 이벤트·혜택 안내를 열 때 다시 받는다. 아래는 2026-11-16의 기록이다. 통계와 생일 이벤트는 서비스 기능 밖의 목적이라 수집 목적에 적는다. 이벤트·혜택 안내는 선택 동의로 따로 받는다. 2026-11-16에 만들었다: 동의 둘을 `users`의 시각 칸(V8)에 둔다. 이메일 가입은 생년월일·성별을 넣으려면 수집·이용 동의가 있어야 한다. 구글 가입은 구글 동의 화면에서 범위를 허락한 것을 이 동의로 남기고, 로그인·회원가입 화면이 무엇을 왜 받는지 알린다. 이벤트 안내 동의는 이메일 가입에서만 받는다. 동의를 거두는 API는 아직 없다(로그인 문서 4.1).
8. **통계는 서비스 전체 기준, 운영자만 본다.** 5명 그룹의 나이·성별·연차 분포는 사람을 특정할 수 있어 그룹 단위로 보여 주지 않는다.
9. **생일 이벤트에 필요한 것.** 줄 혜택(예: LLM 사용량 추가, `llm_usage`로 센다), 매일 생일자를 찾는 예약작업, 알림 메일(인증 메일 발송 수단을 같이 쓴다).
10. **공개 범위.** 카드처럼 "나만 보기" 하나. 그룹에는 보이지 않는다.
11. **고칠 곳.** 로그인 문서의 `users` 테이블과 가입 API, 구글 로그인 범위, 회원가입 화면(지금 표시 이름·이메일·비밀번호)에 생년월일·성별을 더한다(2026-11-16 고쳤다가 2026-11-17에 뺐다. 회원가입 화면은 표시 이름·이메일·비밀번호 그대로다). 경험카드 문서의 추출 작업·프롬프트·결과 화면에 프로필 칸을 더한다.
