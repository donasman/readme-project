## 백엔드

### 2단계. LLM 바탕 만들기(`llm` 패키지)

이후의 카드 추출, 프로필, 공고 분석, OCR 대체, 메일 분류가 모두 이것을 쓴다.

2-1~2-5는 끝났다(위 "끝난 것", 경험카드 문서 4.5). 남은 것은 실제 키로 한 번 불러 보는 확인이다. 돈이 들어 사용자가 시킬 때 한다. 자소서 초안(`high`)의 기능 이름은 10단계에서 더한다.

### 3~7단계

모두 끝났다(위 "끝난 것"). 7-1(구글 OAuth 클라이언트)은 운영에 있다.

남은 결정(그 기능을 다시 볼 때):

- 6-3: 프로필의 자격증·어학·학력을 공고 요건 대조에 쓸지. 지금은 카드 태그만 본다(공고 문서 4.8).
- 4-4: 동의를 보고 거두는 API가 아직 없다. 이벤트·생일 메일(10단계)을 보내기 전에 있어야 한다. 이벤트 안내 동의는 2년마다 다시 받는다(로그인 문서 4.1).
- 5-5: 조각마다 나뉘어 나온 학력·경력은 처음 나온 조각의 줄만 프로필에 들어간다(코드의 shortcut 주석).

### 9단계. 메일 자동화

서버(9-1~9-4)는 끝났다(위 "끝난 것", `docs/리드미_설계_메일.md`). 받는 Worker 초안은 `deploy/cloudflare/inbound-mail-worker.js`다.

남은 것: 수신 전용 도메인을 산 뒤(운영 8-1) Worker를 올리고 실제 메일로 확인한다(메일 설계 6절). 원문에 `Authentication-Results`가 어떻게 오는지, Gmail 자동 전달의 봉투 주소, Worker가 실패할 때 다시 보내는지를 아직 보지 못했다. 화면(9-5)은 프런트엔드에 있다.
