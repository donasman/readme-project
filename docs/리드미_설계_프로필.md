# 리드미 설계: 기본 프로필

2026-11-16. `docs/리드미_설계_프로필_방향.md`(2026-11-15)를 설계로 키운 것이다. 서버에 들어갔다(`profile` 패키지, `V6__profiles.sql`).

- 방향과 그 이유(받는 값, 받지 않는 값, 구글 검토, 동의): 프로필 방향 문서
- 가입 값(생년월일·성별)을 넣는 것: 로그인 문서 4.1(2026-11-16). 2026-11-17에 뺐다: 가입과 구글은 프로필에 아무것도 넣지 않고, 성별 칸은 지웠다(`V11`)
- 자료에서 프로필 칸을 뽑는 것: 남은 작업 5단계, 경험카드 문서
- 화면: 설정의 기본 프로필(12차 시안, 2026-11-17)과 카드 뽑기 결과의 프로필 칸 확인

## 1. 범위

사람마다 프로필 한 벌. 인적사항(이름, 생년월일)과 매칭용 칸(학력, 자격증, 어학, 경력)이다. 나만 본다(그룹에 보이지 않는다). 이 문서는 테이블과 읽기·고치기 API까지다. 성별은 2026-11-17에 뺐다(PR1).

이 문서에 없는 것: 가입 때 받는 값과 동의(로그인 문서 4.1. 여기는 4.2의 받는 쪽만 적는다), 자료에서 뽑은 값으로 빈 칸 채우기(5단계), 공고 요건과 대조하기(6-3), 통계(10단계).

## 3. 테이블

| 테이블 | 내용 |
|---|---|
| `profiles` | 사람마다 한 행. 이름, 생년월일(성별 칸은 2026-11-17에 지웠다) |
| `profile_educations` | 학력: 학교, 전공, 졸업(예정) 년월, 학점, 만점 |
| `profile_certificates` | 자격증: 이름(대표 표기), 취득 년월 |
| `profile_languages` | 어학: 시험, 점수, 응시 년월 |
| `profile_careers` | 경력: 회사, 시작·끝 년월(끝이 없으면 재직 중), 직무 |

모두 `profile` 패키지가 쓴다. 사람이 탈퇴하면 모두 지워진다(`on delete cascade`).

### 3.1 생성 SQL

`V6__profiles.sql`이 원본이다.

```sql
create table profiles (
  user_id     bigint      primary key references users(id) on delete cascade,
  name        varchar(50),                         -- 이력서의 이름. 표시 이름(users.display_name)과 따로다
  birth_date  date,
  gender      varchar(10) check (gender in ('MALE', 'FEMALE')),
  updated_at  timestamptz not null default now()
);

create table profile_educations (
  user_id     bigint       not null references profiles(user_id) on delete cascade,
  seq         integer      not null,
  school      varchar(100) not null,
  major       varchar(100),
  graduation  varchar(7)   check (graduation ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),   -- 졸업(예정) 년월
  gpa         numeric(5,2) check (gpa >= 0),
  gpa_scale   numeric(5,2) check (gpa_scale > 0),                              -- 4.5, 4.3, 100 등
  primary key (user_id, seq),
  check (gpa is null or gpa_scale is null or gpa <= gpa_scale)
);

create table profile_certificates (
  user_id     bigint       not null references profiles(user_id) on delete cascade,
  seq         integer      not null,
  name        varchar(100) not null,               -- 자격증 사전(certificates.yaml)의 대표 표기. 사전에 없으면 넣은 그대로
  acquired    varchar(7)   check (acquired ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),
  primary key (user_id, seq)
);

create table profile_languages (
  user_id     bigint       not null references profiles(user_id) on delete cascade,
  seq         integer      not null,
  test        varchar(50)  not null,               -- TOEIC, OPIc 등
  score       varchar(20)  not null,               -- 900, IH 처럼 시험마다 꼴이 달라 글자로 둔다
  taken       varchar(7)   check (taken ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),
  primary key (user_id, seq)
);

create table profile_careers (
  user_id     bigint       not null references profiles(user_id) on delete cascade,
  seq         integer      not null,
  company     varchar(100) not null,
  start_month varchar(7)   not null check (start_month ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),
  end_month   varchar(7)   check (end_month ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'),   -- null 이면 재직 중
  role        varchar(100),                        -- 직무
  primary key (user_id, seq),
  check (end_month is null or end_month >= start_month)
);
```

2026-11-17에 `V11__drop_gender_and_signup_consents.sql`이 `profiles.gender`를 지웠다(PR1).

## 4. API

| API | 하는 일 |
|---|---|
| `GET /api/me/profile` | 내 프로필. 저장한 적이 없으면 빈 칸과 빈 목록이다 |
| `PUT /api/me/profile` | 모든 칸을 보낸 값으로 바꾸고 바뀐 프로필을 돌려준다. 처음이면 만든다 |

응답(GET과 PUT이 같다):

```json
{
  "name": "김다온", "birthDate": "1999-03-01",
  "educations": [{ "school": "한국대학교", "major": "컴퓨터공학", "graduation": "2024-02", "gpa": 3.80, "gpaScale": 4.50 }],
  "certificates": [{ "name": "컴퓨터활용능력", "acquired": "2022-08" }],
  "languages": [{ "test": "TOEIC", "score": "900", "taken": "2025-01" }],
  "careers": [{ "company": "가나다", "start": "2024-03", "end": null, "role": "백엔드 개발" }],
  "careerMonths": 33, "careerYears": 2
}
```

- 성별은 받지 않는다(2026-11-17, PR1). 응답과 본문에 `gender`가 없다.
- `careerMonths`, `careerYears`는 PR2로 서버가 센다. 보내지 않는다.
- 본문은 응답에서 `careerMonths`, `careerYears`를 뺀 꼴이다. 빠진 칸은 비운 것이다(모든 칸을 바꾼다).

### 4.1 만들면서 정한 것

- 길이는 테이블 칸과 같다. 여러 줄은 각각 20줄까지다.
- 빈 글자는 넣지 않은 것으로 본다(`""` → `null`). 앞뒤 공백을 지운다.
- 꼭 넣어야 하는 칸: 학교, 자격증 이름, 시험과 점수, 회사와 경력의 시작 달.
- 생년월일은 1900-01-01부터 오늘(서울)까지다.
- 처음 저장할 때 프로필 행은 조건이 붙은 native insert(`on conflict do nothing`)로 만든다. 같은 사람이 처음 저장을 두 번 같이 보내도 한 행만 생긴다.
- 자격증 사전은 키워드 사전과 같은 클래스(`keyword/KeywordDictionary.certificates()`)로 읽는다. 대표 표기와 다른 표기만 읽고, "관련 역량"은 공고 대조(6-3)를 만들 때 읽는다.
- 응답에 고친 때(`updated_at`)는 싣지 않는다. 쓰는 화면이 없다.

오류는 공통 400 `INVALID_INPUT` 하나다. 칸끼리 맞지 않을 때는 메시지가 다르다:

| 언제 | message |
|---|---|
| 생년월일이 오늘 뒤이거나 1900년 앞이다 | 생년월일을 확인해 주세요 |
| 학점이 만점보다 크다 | 학점이 만점보다 큽니다 |
| 경력의 끝 달이 시작 달보다 앞이다 | 경력의 끝 달이 시작 달보다 앞입니다 |

년월의 꼴이 틀리거나(`2025-13`) 길이를 넘으면 공통 메시지("입력값을 확인해 주세요")다.

### 4.2 다른 기능이 부르는 것

`profile/Profiles.fillBlanks(userId, ProfileDraft)`(2026-11-16). 자료에서 뽑은 값(5단계)만 쓴다. 가입 값은 2026-11-17에 뺐다.

- 빈 칸만 채운다(방향 문서 2절, 3절 4번). 이름·생년월일은 비어 있을 때만 넣는다. 학력·자격증·어학·경력은 그 목록에 한 줄도 없을 때만 넣는다. 이미 한 줄이라도 있으면 그 목록은 건드리지 않는다(줄끼리 같은지 가리는 규칙을 두지 않으려는 것이다).
- 프로필이 없으면 만든다.
- 사용자가 친 값이 아니라서 틀린 값은 오류 없이 버린다: 꼭 있어야 하는 칸이 빈 줄, `YYYY-MM`이 아닌 년월, 오늘 뒤나 1900년 앞의 생년월일, 만점보다 큰 학점(학점과 만점을 함께 버린다). 경력의 끝이 시작보다 앞이면 끝을 버려 재직 중이 된다. 긴 글은 칸 길이로 자르고, 여러 줄은 20줄까지다. 자격증 이름은 사전의 대표 표기로 바꾼다.

가입과 구글은 프로필에 아무것도 넣지 않는다(2026-11-17, 로그인 문서 4.1). 2026-11-16에는 `auth`가 내는 이벤트(`SignupValues`, `GoogleValues`)로 생년월일·성별을 넣었지만 성별과 함께 뺐다.

## 5. 프런트와 맞출 것

프로필 화면은 2026-11-17에 만들었다(`features/settings/pages/profile-page.tsx`). 아래대로 맞췄다:

1. 위 응답 꼴을 그대로 쓴다. 년월 칸은 `"YYYY-MM"`, 재직 중은 `end: null`이다.
2. 자격증 이름은 저장한 뒤 대표 표기로 돌아온다(컴활 → 컴퓨터활용능력).
3. 연차는 서버의 `careerYears`를 쓴다(화면이 다시 세지 않는다).
