정한 것은 둘이다.

- 층을 넷으로 나눈다: 공용 → 도메인 → 기능 → 앱.
- 공용 부품은 지금 3곳 이상 반복된 것만 뽑는다. 2곳인 것은 다음 화면에서 다시 나오면 뽑는다.

나머지(폴더 이름, 가짜 서버 분리, 5절의 부품 이름)는 이 문서의 안이고 9절에 정할 것으로 남겼다.

## 1. 요약

- 지금 구조의 문제는 "그룹"과 "보는 사람"이 `features/group-posts` 안에 있다는 것이다. 공용 쪽 4곳이 이 기능을 거꾸로 불러온다.
- 그룹과 보는 사람을 `domain`으로 올리고, 헤더와 틀은 `app`으로, 도메인을 모르는 도우미와 부품은 `shared`로 내린다.
- 화면 모양은 바뀌지 않는다. 예외는 7절 5단계의 오류 화면과 `/dev/components` 글자 간격 하나다.
- 순서는 8단계이고 단계마다 커밋한다(7절).

## 2. 층과 폴더

```
src/
├─ app/          앱. 조립하는 곳: 라우터, 틀(헤더), 오류 화면, 시작 설정
├─ features/     기능. 화면 단위: group-posts (이후 auth, cards, postings …)
├─ domain/       도메인. 여러 기능이 함께 쓰는 개념: session, group
├─ shared/       공용. 도메인을 모르는 리드미 코드: 부품, 도우미, 아이콘
├─ components/   받아 온 부품. ui(shadcn), arc(dsui). 옮기지 않는다
├─ mocks/        가짜 서버. 예시 데이터와 메모리 저장소. 백엔드를 연결하면 지운다
├─ index.css
└─ main.tsx
```

| 층 | 폴더 | 불러올 수 있는 것 |
|---|---|---|
| 앱 | `app/` | 기능(각 기능의 `index.ts`만), 도메인, 공용 |
| 기능 | `features/<이름>/` | 도메인, 공용. 다른 기능과 앱은 안 된다 |
| 도메인 | `domain/<이름>/` | 공용, 다른 도메인(group → session 한 방향) |
| 공용 | `shared/`, `components/` | 공용끼리만 |
| 가짜 서버 | `mocks/` | 공용과 타입(`import type`)만. 이 폴더를 부르는 것은 각 층의 `api.ts`뿐이다 |

`components/`를 `shared/` 아래로 옮기지 않는 이유:

- dsui 항목은 설치 위치가 `components/arc/…`로 고정돼 있다(레지스트리 항목의 `target`). 다시 받으면 그 자리에 놓인다.
- shadcn 부품은 `components.json`의 `ui` 별칭을 바꾸면 옮길 수 있다. 다만 받아 온 것을 한 폴더에 두는 편이 "CLI가 쓰는 자리"와 "리드미가 만든 것"을 구분하기 쉽다고 봤다.

## 4. 새로 생기는 것

**도메인**

| 파일 | 내용 |
|---|---|
| `domain/session/types.ts` | `Viewer`(지금의 보는 사람: `id`, `name`) |
| `domain/session/api.ts` | `getViewer()`. 백엔드를 연결하면 `GET /api/me`를 부른다 |
| `domain/session/loader.ts`, `use-viewer.ts` | 뿌리 라우트의 loader와, 화면이 그 값을 읽는 훅. 라우트 id 상수도 여기 둔다 |
| `domain/group/types.ts` | `Group`, `Member`, `Disclosure` |
| `domain/group/api.ts` | `getMyGroups()` |
| `domain/group/loader.ts`, `use-group.ts` | 그룹 라우트의 loader(내 그룹들, 지금 그룹. 없으면 `NotFoundError`)와 `useGroup()` 훅 |
| `domain/group/disclosure.ts` | `DISCLOSURE_LABELS` |

보는 사람은 뿌리 라우트가 한 번, 그룹은 그룹 라우트가 한 번 읽는다. 지금은 틀의 loader와 화면 loader 2개가 같은 값을 따로 돌려주고, 라우트에 붙인 `id: "group"`은 쓰는 곳이 없다.

**공용 도우미**

| 파일 | 내용 |
|---|---|
| `shared/lib/errors.ts` | `NotFoundError`. 지금은 "그룹", "공고" 둘만 받는다. 무엇을 못 찾았는지 글자로 받게 한다 |
| `shared/lib/paths.ts` | 주소를 만드는 함수: `paths.group(id)`, `paths.groupPosts(id)`, `paths.groupPost(id, postId)`. 지금은 6곳에서 직접 만든다 |
| `shared/lib/router.ts` | 주소의 `?` 뒤만 바뀌면 다시 읽지 않는 `shouldRevalidate`. 지금은 같은 함수가 2개다 |
| `shared/lib/date.ts`, `korean.ts` | 3절 참고 |

**기능의 겉면**

| 파일 | 내용 |
|---|---|
| `features/group-posts/routes.tsx` | 이 기능의 라우트 묶음. 화면과 loader를 필요할 때 불러오게(`lazy`) 적고, `handle: { section: "posts" }`를 붙인다 |
| `features/group-posts/index.ts` | 밖에서 불러올 수 있는 것. 지금은 라우트 묶음 하나다 |

헤더는 `useMatches()`로 `handle.section`을 읽어 지금 메뉴를 표시한다. 멤버 화면이 생기면 그 기능의 라우트에 `section: "members"`를 붙이면 된다.

**가짜 서버**

| 파일 | 내용 |
|---|---|
| `mocks/example-data.ts` | 지금의 예시 데이터 |
| `mocks/db.ts` | 메모리 저장소와 읽기·고치기 함수(그룹 찾기, 공고 찾기, 관심 바꾸기, 댓글 달기, 열린 공고 수 세기) |

따로 두는 이유: `getMyGroups()`의 "공고 N"은 공고 데이터에서 세는 값이다. 그룹은 도메인에, 공고는 기능에 있으므로 예시 데이터를 한쪽에 두면 다른 쪽이 층을 거슬러 불러와야 한다. 각 `api.ts`는 `mocks/db.ts`를 부르는 몇 줄이 되고, 백엔드를 연결할 때 그 줄만 `fetch`로 바꾼다.

- 화면: 모양을 바꾸는 단계가 5단계의 두 화면뿐이므로, 목록과 상세는 바꾸기 전 캡처와 픽셀이 같아야 한다. 2026-11-13에 지금 코드를 1280px·390px, 라이트·다크로 캡처해 `docs/design/shots`와 비교한 값은 차이 0.1~0.4%다.
- 번들: 지금은 JS 한 덩어리 706 kB(gzip 234 kB)다. 6단계 뒤에 다시 잰다.
- 동작: 필터와 정렬이 주소에 남는지, 관심 켜기·끄기, 댓글 달기, 그룹 전환, 없는 그룹·공고 주소의 오류 화면.

## 10. 근거와 확인하지 못한 것

- dsui 설치 위치: `https://dsui.vercel.app/r/segmented-control.json`의 파일마다 `target`이 `components/arc/…`로 적혀 있다. `arc` 안의 부품은 서로를 상대 경로로 불러온다.
- 라우터: 설치된 react-router 8.5.1의 타입에 `lazy`, `handle`, `useMatches`, `useRouteLoaderData`가 있다.
- 반복 횟수와 중복은 2026-11-13의 코드에서 센 것이다.
- 확인하지 못한 것: `components.json` 별칭을 바꾼 뒤 `shadcn add`가 새 위치에 맞게 도는지, `lazy`로 나눈 뒤의 번들 크기.
