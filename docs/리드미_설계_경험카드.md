## 3. 테이블

| 테이블 | 내용 |
|---|---|
| `card_sources` | 올린 자료에서 읽어 낸 본문 |
| `card_extraction_jobs` | 카드 추출 작업의 상태와 진행도 |
| `experience_cards` | 경험카드 본체 |
| `card_tags` | 카드의 태그(키워드 사전의 대표 표기) |

| `llm_usage` | LLM 호출별 토큰 수. 월 크레딧 추적과 나중의 무료 한도에 쓴다 |

`llm_usage`는 `llm` 패키지의 테이블이다. 지금 LLM을 쓰는 곳이 카드 추출뿐이라 이 문서에 둔다.

### 3.1 생성 SQL

`V1__init.sql`의 뒷부분이다. 앞부분(스키마와 계정 테이블)은 로그인 문서 3.1에 있다. 아래는 마이그레이션 파일과 글자가 같다. 고칠 일이 생기면 마이그레이션 파일이 원본이다.

```sql
set search_path to readme;

-- ── 경험카드 ─────────────────────────────────────────────────────────
create table card_sources (
  id           bigint generated always as identity primary key,
  user_id      bigint      not null references users(id) on delete cascade,
  kind         varchar(10) not null check (kind in ('FILE', 'TEXT')),
  file_name    varchar(255),
  content_type varchar(100),
  byte_size    bigint,
  sha256       char(64)    not null,             -- 같은 자료를 다시 올렸는지 판별
  body         text        not null,             -- 읽어 낸 본문. 숫자 원문 대조에 쓴다
  char_count   integer     not null,
  created_at   timestamptz not null default now(),
  unique (user_id, sha256)
);

create table card_extraction_jobs (
  id            bigint generated always as identity primary key,
  user_id       bigint      not null references users(id) on delete cascade,
  source_id     bigint      not null references card_sources(id) on delete cascade,
  status        varchar(10) not null check (status in ('QUEUED', 'RUNNING', 'DONE', 'FAILED')),
  total_parts   integer     not null,            -- 본문을 5,000자씩 나눈 조각 수 = LLM 호출 수
  done_parts    integer     not null default 0,
  error_message text,
  created_at    timestamptz not null default now(),
  started_at    timestamptz,
  finished_at   timestamptz
);
create index card_extraction_jobs_user_idx on card_extraction_jobs (user_id, created_at desc);

create table experience_cards (
  id               bigint generated always as identity primary key,
  user_id          bigint       not null references users(id) on delete cascade,
  title            varchar(200) not null,
  period           varchar(50),                  -- '2025-03 ~ 2025-06' 글자 그대로
  org              varchar(200),
  role             varchar(200),
  summary          varchar(200),                 -- 60자를 넘으면 경고만 낸다
  situation        text,
  task             text,
  action           text,
  result           text,
  verified         boolean      not null default false,
  verified_at      timestamptz,
  visibility       varchar(10)  not null default 'PRIVATE' check (visibility in ('PRIVATE')),
  source_id        bigint references card_sources(id) on delete set null,
  job_id           bigint references card_extraction_jobs(id) on delete set null,
  extraction_notes jsonb,                        -- 추출 때 생긴 안내 목록. 카드를 확인하면 비운다
  created_at       timestamptz  not null default now(),
  updated_at       timestamptz  not null default now()
);
create index experience_cards_user_idx on experience_cards (user_id, updated_at desc);

create table card_tags (
  card_id bigint       not null references experience_cards(id) on delete cascade,
  tag     varchar(100) not null,                 -- 키워드 사전의 대표 표기
  primary key (card_id, tag)
);
create index card_tags_tag_idx on card_tags (tag);

create table card_usable_for (
  card_id       bigint      not null references experience_cards(id) on delete cascade,
  question_type varchar(10) not null
    check (question_type in ('지원동기', '직무역량', '협업', '문제해결', '성장', '기타')),
  primary key (card_id, question_type)
);

create table card_facts (
  card_id bigint       not null references experience_cards(id) on delete cascade,
  seq     integer      not null,                 -- 화면에 보이는 순서
  body    varchar(500) not null,
  primary key (card_id, seq)
);

-- ── LLM 사용 기록 ────────────────────────────────────────────────────
create table llm_usage (
  id            bigint generated always as identity primary key,
  user_id       bigint references users(id) on delete set null,
  feature       varchar(30) not null,            -- 'EXP_EXTRACT' 등
  model         varchar(50) not null,
  input_tokens  integer     not null,
  output_tokens integer     not null,
  created_at    timestamptz not null default now()
);
create index llm_usage_user_idx on llm_usage (user_id, created_at);
```

### 3.2 설계 이유

- **카드 칸은 jobfit 형식 그대로다.** title, period, org, role, tags, summary, star 4칸, facts, usable_for, verified. jobfit의 영문 `id`(exp-…)는 DB의 `id`로 대신한다.
- **`period`는 글자 그대로 둔다.** jobfit이 "2025-03 ~ 2025-06", "2026 ~ 현재"처럼 여러 꼴을 받는다. 기간순 정렬이 필요해지면 날짜 칸을 더한다.
- **문항 유형 값은 한글 그대로다.** jobfit 프롬프트와 테스트가 이 이름을 쓴다.
- **자료 본문을 보관하는 이유.** jobfit은 추출된 카드의 숫자를 자료 원문과 대조해, 원문에 없는 숫자가 든 fact는 빼고 star의 숫자는 `[확인 필요: 숫자]`로 바꾼다. 카드를 확인할 때도 원문을 다시 본다. 사용자가 자료를 지우면 카드는 남고 `source_id`만 빈다.
- **`llm_usage`.** 지금 월 100달러 크레딧을 쓰므로 기능별·사용자별 토큰 수를 처음부터 쌓아 둔다.

### 3.3 확인한 것

임시 PostgreSQL 16에 V1을 실행하고 아래를 SQL로 돌려 봤다. V1은 계정 테이블과 함께 확인했다.

| 확인 | 결과 |
|---|---|
| 자료 → 추출 작업 → 카드·태그·유형·fact 저장 | 통과 |
| 카드 목록(태그 + 문항 유형 + 확인 필요 필터), 태그별 카드 수 | 통과 |
| 문항 유형이 아닌 값, 같은 자료 두 번 | 모두 막힘 |
| 자료 삭제 시 카드는 남고 `source_id`·`job_id`만 빈다 | 통과 |

확인하지 않은 것: JPA 매핑. 서버에 카드 코드가 아직 없다.

2026-11-15: 카드 테이블 4개(`experience_cards`, `card_tags`, `card_usable_for`, `card_facts`)의 JPA 매핑을 통합 테스트로 확인했다(`ddl-auto: validate`, 만들기·고치기·지우기·확인). 자료·추출 테이블 2개는 아직 매핑하지 않았다.

## 4. API

공통 규칙과 공통 오류 코드는 구조 문서 5절에 있다. 경험카드의 오류 코드는 4.3에 있다.

### 4.1 경험카드 (8개)

| 메서드·주소 | 하는 일 | 비고 |
|---|---|---|
| `GET /api/cards` | 카드 목록 | 필터: `tag`, `type`, `verified`, `jobId`, `q` |
| `GET /api/cards/tags` | 내 카드에 쓰인 태그와 카드 수 | 목록 화면의 태그 필터 |
| `POST /api/cards` | 카드 직접 만들기 | |
| `GET /api/cards/{id}` | 카드 상세 | 검사 결과 `issues` 포함 |
| `PUT /api/cards/{id}` | 카드 수정 | 태그는 대표 표기로 바꿔 저장. `issues` 반환 |
| `DELETE /api/cards/{id}` | 카드 삭제 | |
| `POST /api/cards/{id}/verify` | 카드 확인 | `verified = true`. star에만 있는 숫자를 facts로 옮긴다 |
| `GET /api/keywords?q=` | 태그 입력 자동완성 | 다른 표기를 쳐도 대표 표기를 돌려준다(k8s → Kubernetes) |

### 4.2 자료와 추출 (5개)

| 메서드·주소 | 하는 일 | 비고 |
|---|---|---|
| `POST /api/card-sources` | 파일을 올리거나 글을 붙여넣는다. 서버가 본문을 읽어 저장 | 응답: 글자 수, 조각 수(= LLM 호출 수), 이미 올린 자료인지 |
| `GET /api/card-sources` | 올린 자료 목록 | |
| `DELETE /api/card-sources/{id}` | 자료 본문 삭제 | 카드는 남는다 |
| `POST /api/card-sources/{id}/extract` | 추출 작업 시작 | 202와 작업 번호 |
| `GET /api/card-extractions/{jobId}` | 작업 상태: 진행 조각 수, 만든 카드 수, 건너뛴 카드 | 프런트가 몇 초마다 조회 |

올리기와 추출을 나눈 이유: 추출 전에 "조각 3개, LLM 호출 3회"를 보여 주고 시작할 수 있다.

### 4.3 만들면서 정한 것

2026-11-15에 4.1의 8개를 만들며 정한 것(화면·API 대응 문서 3절 22번, 25번). 가정 C1~C5는 초안대로다.

- **`sourceName`**(22번): 카드 응답에 싣는다. 카드를 뽑은 자료의 `file_name`이다. 자료가 없거나(직접 만든 카드, 자료를 지운 카드) 붙여넣은 글(`kind = TEXT`, 파일 이름이 없다)이면 null이다.
- **태그 자동완성 `GET /api/keywords?q=`**(25번): 프런트의 꼴 그대로 `[{ "label": "Kubernetes", "note": "k8s의 대표 표기" }]`다. `label`은 대표 표기, `note`는 걸린 다른 표기를 적은 글이고 대표 표기에 걸렸으면 null이다. 친 글자와 똑같은 표기, 그 글자로 시작하는 표기, 그 글자가 든 표기의 순이고(대소문자 무관), 같으면 사전 순서다. 대표 표기 하나는 한 번만 나오고 많아야 10개다. 빈 글자면 빈 목록이다.
- **태그**: 대표 표기로 바꿔 저장한다(`스프링부트`, `java` → `Spring Boot`, `Java`). 사전에 없는 태그는 친 그대로(앞뒤 공백만 지운다) 저장하고 검사가 경고한다. 같은 태그는 한 번만 둔다.
- **남의 카드**: 없는 카드와 같은 404 `CARD_NOT_FOUND`다. 둘을 구분하지 않는다.
- **검사 결과 `issues`**: 카드 응답마다(목록, 상세, 만들기, 고치기, 확인) 저장된 값으로 매긴다. 규칙은 jobfit `check_cards`(7절)를 옮긴 `card/CardRules`다. jobfit과 다른 점은 셋이다. 칸 이름과 글을 화면의 말로 쓴다(`"field": "요약"`, "요약이 72자입니다(60자 이내)"). id·예시 카드·verified 검사는 리드미에 해당하지 않아 뺐다(확인 여부는 화면이 따로 보여 준다). 사전에 없는 태그를 경고한다.
- **카드 확인 `POST /api/cards/{id}/verify`**: `verified = true`, `verified_at`은 지금이다. STAR에만 있는 숫자마다 그 숫자가 든 STAR 문장을 근거 숫자 끝에 더한다(120자가 넘으면 숫자 앞뒤만). jobfit `ground_star`에서 사람이 맞다고 한 길(`vouched`)과 같다. `extraction_notes`는 비운다(null). 다시 확인해도 된다. 더할 숫자가 없으면 근거 숫자는 그대로고 `verified_at`만 바뀐다.
- **목록 거르기**: `tag`, `type`, `verified`, `jobId`, `q`를 함께 쓸 수 있다. `tag`는 다른 표기도 대표 표기로 바꿔 찾고, `type`은 다른 이름(기술역량, 팀워크)도 받는다. `q`는 제목, 기간, 어디서, 맡은 일, 요약, STAR, 태그, 근거 숫자에 그 글자가 들었는지 본다. 대소문자를 가리지 않고 `%`·`_`도 글자 그대로다.
- **입력의 길이**: 칸의 길이와 같다(제목 200, 기간 50, 어디서·맡은 일·요약 200, 태그 하나 100, 근거 숫자 하나 500). 칸에 길이가 없는 것은 STAR 한 칸 2,000자, 태그 30개, 근거 숫자 50개까지 받는다(2026-11-15 정함). 카드 검사(숫자 뽑기)가 글 길이의 제곱으로 오래 걸려서다. 막지 않았을 때 4만 자짜리 STAR 한 칸("-a-a-a…")의 검사가 16초 넘게 걸렸고, 목록 요청 다섯 개면 DB 연결 다섯 개를 모두 붙잡았다. 그래서 검사는 DB 쿼리가 끝난 뒤에 한다. 문항 유형은 6종으로 읽은 값만 받는다. 읽을 수 없는 값이 하나라도 있으면 400이다.

만들면서 채운 빈칸:

- 목록(`GET /api/cards`)과 상세는 같은 꼴이다. 카드 확인 화면이 `?verified=false`로 받은 카드를 한 장씩 보여 주므로 목록에도 STAR, 근거 숫자, 검사 결과가 있어야 한다. 카드 수가 적어 한 번에 다 읽는다.
- 목록은 최근에 고친 카드가 앞이다(`updated_at` 역순, 같으면 id 역순). 카드 확인도 고친 것으로 본다.
- 응답의 태그는 이름순이다(대소문자 무관, 영문이 한글보다 앞). `card_tags`에 순서 칸이 없어서다. 문항 유형은 6종의 순서(지원동기, 직무역량, …), 근거 숫자는 넣은 순서다.
- 제목만 꼭 넣는다(빈 제목은 400). 빈 요약·태그·문항 유형은 저장하고 검사가 오류로 알린다. jobfit도 저장된 카드를 검사한다.
- 앞뒤 공백을 지우고 빈 글자는 null로 둔다. STAR의 빈 칸도 null로 두고 응답에서는 빈 글자다. 응답의 `summary`도 없으면 빈 글자다. 빈 태그·근거 숫자는 400이다.
- 고치기(PUT)는 모든 칸을 보낸 값으로 바꾼다. 확인 여부, 자료, 추출 작업, 추출 안내는 그대로다. 근거 숫자는 보낸 순서대로 `seq` 1부터 다시 매긴다.
- 직접 만든 카드는 확인 전(`verified = false`)이다(C5의 추출된 카드와 같다).
- 지우기는 204다. 태그, 문항 유형, 근거 숫자도 지워진다.
- `GET /api/cards/tags`는 `[{ "name": "Spring Boot", "count": 2 }]`다. 많이 쓰인 태그가 앞, 같으면 이름순이다.
- `visibility`는 DB 값 `"PRIVATE"` 그대로 보낸다. 프런트 타입이 이 값이다.
- 카드 확인이 근거 숫자에 무엇을 넣었는지 알리는 글(jobfit이 확인 뒤 보여 주는 줄)은 응답에 싣지 않는다. 더한 문장은 근거 숫자에 보인다.
- 카드 확인은 아직 자료 원문을 보지 않는다. jobfit은 원문에 그 숫자가 있으면 STAR 문장 대신 원문 문장을 넣는다. 자료·추출(4.2)을 만들 때 원문 쪽을 옮겨 맞춘다(구조 문서 10절).

카드 검사(`issues`)의 항목:

| level | field | 언제 |
|---|---|---|
| 오류 | 제목, 태그, 요약, 쓸 문항 유형 | 비었다 |
| 경고 | 요약 | 60자를 넘는다. 이모지도 한 글자로 센다 |
| 경고 | 태그 | 대표 표기가 아니다(API로 저장한 카드는 대표 표기라 나오지 않는다), 사전에 없다 |
| 오류 | 쓸 문항 유형 | 6종이 아니다(API로는 저장되지 않는다) |
| 경고 | 쓸 문항 유형 | 다른 이름이다(API로는 6종으로 바꿔 저장한다) |
| 경고 | 근거 숫자 | 없다 |
| 경고 | STAR | 빈 칸이 있다, 근거 숫자에 없는 숫자가 있다 |
| 경고 | 기간 | 읽을 수 없다(`2025-03 ~ 2025-06`, `2025.03`, `2026 ~ 현재` 같은 꼴이 아니다) |

오류 코드(`card/CardErrorCode`):

| code | HTTP | 언제 |
|---|---|---|
| `CARD_NOT_FOUND` | 404 | 카드 상세·고치기·지우기·확인: 카드가 없거나 남의 카드다. 둘을 구분하지 않는다 |

길이나 개수를 넘은 값, 빈 제목, 빈 태그·근거 숫자, 읽을 수 없는 문항 유형(본문의 `usableFor`, 목록의 `type`), 꼴이 틀린 거르기 값(`verified=maybe`, `jobId=abc`)은 공통 400 `INVALID_INPUT`이다(구조 문서 5.2). 로그인하지 않았으면 `GET /api/keywords`도 401이다.

## 5. 화면과 API

| 화면 | 쓰는 API |
|---|---|
| 카드 목록 | `GET /api/cards`, `GET /api/cards/tags` |
| 카드 상세·편집 | `GET`·`POST`·`PUT`·`DELETE /api/cards`, `GET /api/keywords` |
| 자료로 카드 만들기 | `POST`·`GET`·`DELETE /api/card-sources`, `POST …/extract`, `GET /api/card-extractions/{jobId}` |
| 카드 확인 | `GET /api/cards?verified=false&jobId=`, `PUT /api/cards/{id}`, `POST /api/cards/{id}/verify`, `DELETE /api/cards/{id}` |

화면별로 보이는 값은 화면·API 대응 문서 2.2절에 있다. 시안이 요구하는데 이 문서에 없는 것: 카드를 뽑은 자료 원문(3절 21번), 진행 중인 추출 작업 찾기(23번), 받는 자료의 형식과 크기(24번). 자료 이름(22번)과 태그 자동완성의 응답 모양(25번)은 2026-11-15에 정해 4.3에 넣었다.

## 6. 프런트와 맞출 것

2026-11-13에 본 것: 프런트의 `getUnverifiedCards`는 `jobId` 없이 확인 전 카드를 모두 받고, `uploadSource`는 자료와 조각 수(`chunks`)를 받는다.

2026-11-15에 카드 API를 만들며 프런트의 `features/cards/types.ts`, `api.ts`, 가짜 서버(`mocks/cards-db.ts`)와 비교한 것. 설계 4.1과 프런트가 다른 곳은 프런트를 따랐다.

| 곳 | 서버 | 프런트 | 맞출 쪽 |
|---|---|---|---|
| 목록 `GET /api/cards` | 상세와 같은 꼴(`CardDetail`)의 배열 | `getCards`는 목록 칸(`ExperienceCard`)만 쓰고, `getUnverifiedCards`(`?verified=false`)는 `CardDetail`을 쓴다 | 그대로 쓰면 된다. `getUnverifiedCards`는 `jobId` 없이 불러도 된다 |
| `issues[].field` | 화면의 칸 이름: 제목, 기간, 태그, 요약, 쓸 문항 유형, 근거 숫자, STAR | 가짜 서버는 "요약", "근거 숫자", "결과" | 설계 4.1의 예(`"field": "summary"`)가 아니라 가짜 서버처럼 화면의 말로 했다. STAR 칸의 검사는 네 칸을 묶어 "STAR"다 |
| `issues`의 항목 | jobfit `check_cards`의 규칙(4.3의 표) | 가짜 서버는 결과의 `[확인 필요: …]`를 경고로 낸다 | 서버는 `[확인 필요]`를 검사하지 않는다(jobfit도 숫자로 보지 않는다). 추출 안내(`extractionNotes`)와 고치기 화면의 안내가 알린다 |
| `tags` 순서 | 이름순(대소문자 무관) | 넣은 순서로 보여 준다 | 저장한 뒤에는 이름순으로 돌아온다. 넣은 순서를 지키려면 `card_tags`에 순서 칸이 필요하다(마이그레이션) |
| `usableFor` 순서 | 6종의 순서 | 고치기 화면이 6종의 순서로 보낸다 | 같다 |
| `sourceName` | 파일 이름. 붙여넣은 글이면 null | 가짜 서버는 붙여넣은 글을 "붙여넣은 글"로 준다 | 카드 확인 화면은 null이면 "자료에서 뽑은 카드입니다."를 쓴다 |
| `sourceExcerpt` | 싣지 않는다 | `string \| null` | 화면·API 대응 문서 3절 21번이 정해지기 전까지 프런트가 없는 값(undefined)을 null처럼 다룬다 |
| `GET /api/keywords` | 많아야 10개. 다른 표기는 같은 것·시작·포함 모두 찾는다 | 가짜 서버는 5개, 다른 표기는 똑같을 때만 찾는다 | 화면은 그대로 쓰면 된다 |
| 태그 자동완성의 `note` | 사전에 적힌 표기("k8s의 대표 표기") | 가짜 서버는 친 그대로("K8S의 대표 표기") | 화면은 그대로 쓰면 된다 |
| 오류 | 남의 카드·없는 카드는 404 `CARD_NOT_FOUND`, 잘못된 입력은 400 `INVALID_INPUT` | 가짜 서버는 `NotFoundError` | `api.ts`를 서버로 바꿀 때 404를 `NotFoundError`로 바꾼다 |

## 7. jobfit에서 Java로 옮길 것

| jobfit | 줄 수 | 옮길 부분 | 쓰는 곳 |
|---|---|---|---|
| `clean/keywords.py` | 146 | 사전 읽기, `normalize`(대표 표기), `expand`(포함 관계) | 사전 읽기와 `normalize`는 태그 저장, 자동완성. `expand`는 공고 매칭(카드 태그를 넓혀 공고 요건에 맞출 때. Spring Boot → Spring → Java)이고 태그 저장·자동완성에는 쓰지 않는다 |
| `numbers.py` | 252 | `extract`, `same_value` | 카드 검사, 추출 정리 |
| `experiences.py` | 354 중 앞 215줄 | `check_cards`, `normalize_type`, `loose_star_numbers`, 기간 정규식 | 카드 응답의 `issues` |
| `ai/exp_extract.py` | 642 중 일부 | `_split`(5,000자 조각), `normalize_cards`, `ground_star`, `fit_existing` | 추출 작업, 카드 확인 |
| `prompts/exp-extract.md` | | 프롬프트 그대로 | 추출 작업 |

- **순서표와 다른 점**: 정리 문서의 순서표는 숫자 정규화를 5번(자소서 초안)에 뒀다. 그런데 카드 검사와 추출 정리가 `numbers.py`의 `extract`·`same_value`를 쓴다. 1번과 함께 옮겨야 한다.
- 옮기지 않는 부분: `experiences.py` 뒤쪽의 YAML 파일 고치기, `exp_extract.py`의 파일 스캔과 진행 상태 파일.
- 카드 검사 규칙(`check_cards`): 필수 칸(title, tags, summary, usable_for) 비었으면 오류, summary 60자 초과 경고, 태그가 대표 표기가 아니면 경고, 문항 유형이 6종이 아니면 오류, facts 없음 경고, star 빈 칸 경고, star에만 있는 숫자 경고, 기간을 읽을 수 없으면 경고.
