# 리드미 설계: 그룹

2026-11-13 기준. 그룹(만들기, 멤버, 공개 범위, 나가기, 초대)의 테이블과 API다. 그룹에 올린 공고와 내 공고는 `claude/리드미_설계_공고.md`에 있다. 초안이고, 2절의 가정은 바꿀 수 있다.

2026-11-13에 `리드미_설계_그룹_공고.md`를 그룹과 공고로 나눈 앞쪽이다. 가정 번호를 G1~G3으로 새로 매겼다. 옛 번호와 절이 어디로 갔는지는 옛 문서에 남긴 표에 있다.

- 백엔드 구조(패키지, 공통 API 규칙, 공통 오류 코드, 만든 API): `claude/리드미_백엔드_구조.md`
- 그룹 공고·내 공고: `claude/리드미_설계_공고.md`
- 계정 테이블: `claude/리드미_설계_로그인.md`
- 화면마다 쓰는 API와 설계에 없는 것: `claude/리드미_화면_API_대응.md`

- 화면이 기대는 응답 모양: `frontend/src/domain/group/types.ts`, 초대 미리 보기는 `frontend/src/features/auth/types.ts`의 `InviteView`

## 1. 범위

| 화면 | 이 문서의 것 |
|---|---|
| 그룹 화면의 헤더(그룹 전환 메뉴) | 내 그룹 목록 |

## 3. 테이블

| 테이블 | 내용 |
|---|---|
| `groups` | 그룹. 이름, 표시 글자 |
| `group_members` | 그룹 × 사용자. 역할(그룹장·멤버), 이 그룹에 정한 공개 범위 |
| `group_invites` | 초대 링크의 토큰(해시로 보관), 만료 시각 |

### 3.1 생성 SQL

`V3__groups.sql`의 앞부분이다. V3 한 파일에 그룹과 그룹 공고 테이블이 함께 있고, 뒷부분은 공고 문서 3.1에 있다. 아래는 마이그레이션 파일과 글자가 같다. 고칠 일이 생기면 마이그레이션 파일이 원본이다.

```sql
-- 리드미 V3: 그룹 · 그룹 공고
set search_path to readme;

-- ── 그룹 ─────────────────────────────────────────────────────────────
create table groups (
  id         bigint generated always as identity primary key,
  name       varchar(50) not null,
  mark       varchar(4)  not null,               -- 헤더 동그라미 안의 글자. 비워 보내면 서버가 이름 첫 글자를 넣는다
  created_by bigint references users(id) on delete set null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table group_members (
  group_id   bigint      not null references groups(id) on delete cascade,
  user_id    bigint      not null references users(id)  on delete cascade,
  role       varchar(10) not null default 'MEMBER'  check (role in ('LEADER', 'MEMBER')),
  disclosure varchar(10) not null default 'APPLIED' check (disclosure in ('INTEREST', 'APPLIED', 'PROGRESS')),
  joined_at  timestamptz not null default now(),
  primary key (group_id, user_id)
);
create unique index group_members_leader_key on group_members (group_id) where role = 'LEADER';  -- 그룹장은 한 명
create index group_members_user_idx on group_members (user_id);

create table group_invites (
  id         bigint generated always as identity primary key,
  group_id   bigint      not null references groups(id) on delete cascade,
  token_hash char(64)    not null unique,        -- 토큰 원문은 초대 링크에만 있다. DB에는 SHA-256
  created_by bigint references users(id) on delete set null,
  expires_at timestamptz not null,
  revoked_at timestamptz,
  created_at timestamptz not null default now()
);
create index group_invites_group_idx on group_invites (group_id);
```

### 3.2 설계 이유

- **그룹장은 부분 유일 인덱스로 한 명만 둔다.** 역할은 계정이 아니라 그룹 가입 정보에 있다(정리 문서 7절의 제안).
- **`groups`라는 이름.** PostgreSQL에서는 따옴표 없이 테이블 이름으로 쓸 수 있다(실행해 확인했다).
- **그룹의 멤버만 그룹 안의 것을 본다.** 다른 기능은 `group/GroupAccess.requireMember`로 멤버인지 먼저 본다(G3).

### 3.3 확인한 것

임시 PostgreSQL 16.15에 V1, V2, V3를 차례로 실행하고 아래를 SQL로 돌려 봤다. V3는 공고 테이블과 함께 확인했다(공고 문서 3.3).

| 확인 | 결과 |
|---|---|
| V1·V2 위에 V3 적용, 새 테이블 9개 생성 | 통과 |
| 내 그룹 목록: 그룹장, 내 공개 범위, 멤버, 열린 공고 수(내린 공고와 마감된 공고 제외) | 통과 |
| 그룹장 두 명, 정해지지 않은 공개 범위 | 모두 막힘 |
| 그룹 나가기: 그 그룹의 관심은 지워지고 내 공고와 댓글은 남는다 | 통과 |
| 계정 삭제: 멤버·관심·내 공고는 지워지고, 올린 공고와 댓글은 올린 사람·쓴 사람만 빈다 | 통과. 그룹장이 탈퇴하면 그룹장 없는 그룹이 남는다(9절) |
| 그룹 삭제: 그룹 공고·관심·댓글은 지워지고 공고 본체와 내 공고는 남는다 | 통과 |

2026-11-13 서버에서 더 확인한 것: V3 를 이 절의 SQL 그대로 `V3__groups.sql`로 넣어 Flyway 가 PostgreSQL 16 에 적용했고, 복합 키 테이블(`user_postings`, `group_post_interests`)의 JPA 매핑이 `ddl-auto: validate`를 통과했다. 목록 쿼리의 속도는 아직 재지 않았다.

## 4. API

공통 규칙과 공통 오류 코드는 구조 문서 5절에 있다.

| 메서드·주소 | 하는 일 | 비고 |
|---|---|---|
| `GET /api/groups` | 내가 속한 그룹들 | 화면의 `Group` 모양: 멤버 목록(들어온 날 포함), 그룹장, 열린 공고 수, 내 공개 범위, 가장 가까운 마감 |
| `POST /api/groups` | 그룹 만들기 | `name`, `mark`(비우면 이름 첫 글자). 만든 사람이 그룹장이 된다 |
| `PUT /api/groups/{groupId}/me/disclosure` | 이 그룹에 보일 내 공개 범위 바꾸기 | `interest` · `applied` · `progress` |
| `DELETE /api/groups/{groupId}/me` | 그룹 나가기 | 그룹장이면 409 `LEADER_CANNOT_LEAVE`(G2) |
| `POST /api/groups/{groupId}/invites` | 초대 링크 만들기 | 응답: 링크, 만료 시각 |
| `GET /api/groups/{groupId}/invites` | 살아 있는 초대 보기 | 2026-11-15. 만료·취소되지 않은 것. 링크는 다시 보여 줄 수 없다 |
| `DELETE /api/groups/{groupId}/invites/{inviteId}` | 초대 취소 | 2026-11-15. 만든 사람과 그룹장만. 두 번 해도 204 |
| `GET /api/group-invites/{token}` | 초대 미리 보기 | 2026-11-15. 로그인 없이 연다. 없는 토큰은 404 `INVITE_NOT_FOUND`, 만료·취소된 토큰은 410 `INVITE_EXPIRED` |
| `POST /api/group-invites/{token}/accept` | 초대 수락 | 이미 멤버면 그대로 성공. 만료·취소된 토큰은 410 `INVITE_EXPIRED` |

### 4.1 만들면서 정한 것

2026-11-15에 정한 것(화면·API 대응 문서 3.1의 1번, 3번, 4번, 5번):

- **초대 미리 보기는 로그인 없이 연다**: `GET /api/group-invites/{token}` 하나만 `permitAll`에 더했다(GET만. 수락은 로그인해야 한다). 손님 화면에도 그룹 이름을 보여 주려는 것이다. 토큰을 아는 사람에게 그룹 이름, 표시 글자, 링크를 만든 사람의 이름, 멤버 수가 보인다. 멤버 이름과 id는 싣지 않는다. 토큰은 수락처럼 SHA-256 해시로 찾는다.
- **살아 있는 초대 보기와 취소**: 멤버는 그룹의 살아 있는 초대(만료되지 않았고 취소되지 않은 것)를 본다. 토큰은 해시로만 있어 목록에 링크는 없다. 취소는 `revoked_at`을 채운다. 링크를 만든 사람과 그룹장만 하고, 다른 멤버는 403 `FORBIDDEN`이다. 두 번 취소해도 204다.
- **멤버가 들어온 날**: `GET /api/groups`의 `members`마다 `joinedAt`을 싣는다. 멤버 화면용 조회를 따로 두지 않았다.
- **그룹별 가장 가까운 마감**: `GET /api/groups`에 그룹마다 싣는다. 마감일이 오늘(한국 날짜) 이후인 공고 가운데 가장 이른 것이다. 상시·확인 필요 공고는 보지 않는다. 없으면 null이다.
- **초대의 값**: G1 그대로 둔다. 멤버 누구나 만들고, 7일 동안 쓰고, 인원 제한이 없다.

만들면서 채운 빈칸(2026-11-13):

- 그룹 만들기는 201 이고, 만든 그룹을 `GET /api/groups`의 한 항목 모양으로 돌려준다. 이름은 앞뒤 공백을 지운다. 표시 글자의 "이름 첫 글자"는 첫 유니코드 글자다.
- 공개 범위 바꾸기는 바뀐 그룹(같은 모양)을 돌려준다. 나가기는 204 다.
- 초대 링크 만들기는 201 과 `{ "link": "<프런트 주소>/invites/<토큰>", "expiresAt": "2026-11-20T00:30:00+09:00" }`이다. 만료 시각은 초 단위다. 프런트의 초대 화면 주소와 다르다(8절 10번).
- 초대 수락은 들어간 그룹(같은 모양)을 돌려준다. 없는 토큰은 404 `INVITE_NOT_FOUND`다. 이미 멤버면 링크가 만료·취소되었어도 성공으로 본다. 로그인한 사람만 수락한다.

만들면서 채운 빈칸(2026-11-15):

- 미리 보기의 칸 이름은 프런트의 `InviteView`를 따랐다: `groupName`, `mark`, `inviterName`, `memberCount`. 쓸 수 있는 링크인지는 상태 코드로 알린다. 200은 쓸 수 있는 링크, 404 `INVITE_NOT_FOUND`는 없는 링크, 410 `INVITE_EXPIRED`는 만료·취소된 링크다(수락과 같다). 프런트 타입과 다른 점은 8절 6번.
- 멤버 수는 링크를 만든 때가 아니라 지금의 수다.
- 로그인한 사람이 이미 멤버여도 미리 보기는 같다. 프런트의 초대 화면이 "이미 멤버"를 따로 보여 주지 않아서다. 이미 멤버인 사람이 수락하면 그대로 성공한다.
- 링크를 만든 사람이 계정을 지웠으면 `inviterName`과 목록의 `createdBy`는 null이다. 만든 사람이 그룹을 나가도 링크는 만료·취소 전까지 쓸 수 있다. 그 링크는 그룹장이 취소한다.
- 살아 있는 초대 목록은 최근에 만든 것이 앞이다. 만든 사람은 다른 응답의 사람 모양(`{ id, name }`)으로 싣는다. 이름만이 아니라 id도 싣는 것은, 프런트가 그룹장이 아닌 멤버에게는 자기가 만든 링크에만 취소를 보이게 하려는 것이다.
- 취소의 검사 순서: 멤버가 아니면 404 `GROUP_NOT_FOUND`, 그 그룹에 그런 초대가 없으면 404 `INVITE_NOT_FOUND`(다른 그룹의 초대도), 만든 사람도 그룹장도 아니면 403 `FORBIDDEN`. 만료된 링크도 취소할 수 있다. 이미 취소한 링크는 처음 취소한 시각을 그대로 둔다.
- 들어온 날은 `group_members.joined_at`의 한국 날짜(`"YYYY-MM-DD"`)다.
- 가장 가까운 마감의 이름과 모양은 프런트의 `nearestDeadline: { date, company, title } | null`을 따랐다. 내 그룹 화면이 "D-3 · 회사 제목"을 보여 주기 때문이다. 그룹에서 내린 공고는 보지 않는다(열린 공고 수와 같다). 마감일 당일은 넣는다(공고 문서 5.4). 같은 날이 여럿이면 공고 목록의 순서(올린 시각의 역순)에서 앞의 것이다.

오류 코드(`group/GroupErrorCode`):

| code | HTTP | 언제 |
|---|---|---|
| `GROUP_NOT_FOUND` | 404 | 그룹이 없거나 멤버가 아니다(G3) |
| `LEADER_CANNOT_LEAVE` | 409 | 그룹장이 나가려 했다(G2) |
| `INVITE_NOT_FOUND` | 404 | 새로. 그런 초대 링크가 없다(주소가 잘렸거나 잘못 옮겨졌다). 취소에서는 그 그룹에 그런 초대가 없다 |
| `INVITE_EXPIRED` | 410 | 미리 보기, 수락: 만료되었거나 취소된 초대 링크 |

초대를 취소할 수 없는 멤버는 공통 403 `FORBIDDEN`이다(구조 문서 5.2).

### 4.2 응답 모양

`GET /api/groups`의 한 항목. 그룹 만들기, 공개 범위 바꾸기, 초대 수락도 이 모양을 돌려준다. `joinedAt`과 `nearestDeadline`은 2026-11-15에 더했다.

```json
{
  "id": 1,
  "name": "백엔드 스터디",
  "mark": "백",
  "members": [
    { "id": 1, "name": "다온", "joinedAt": "2026-11-02" },
    { "id": 2, "name": "가람", "joinedAt": "2026-11-05" }
  ],
  "leaderId": 2,
  "openPostCount": 6,
  "myDisclosure": "applied",
  "nearestDeadline": { "date": "2026-11-16", "company": "예시 커머스", "title": "백엔드 개발자 신입" }
}
```

`GET /api/group-invites/{token}`(초대 미리 보기). 200일 때만 본문이 이 모양이다.

```json
{ "groupName": "백엔드 스터디", "mark": "백", "inviterName": "가람", "memberCount": 4 }
```

`GET /api/groups/{groupId}/invites`(살아 있는 초대). 최근에 만든 것이 앞이다.

```json
[
  {
    "id": 7,
    "createdBy": { "id": 2, "name": "가람" },
    "createdAt": "2026-11-13T00:30:00+09:00",
    "expiresAt": "2026-11-20T00:30:00+09:00"
  }
]
```

## 5. 권한

그룹 API는 초대 미리 보기와 수락 말고는 모두 로그인한 그 그룹의 멤버만 부를 수 있다. 멤버가 아니거나 그룹이 없으면 404 `GROUP_NOT_FOUND`를 준다(G3).

| 동작 | 할 수 있는 사람 |
|---|---|
| 보기, 초대 링크 만들기, 살아 있는 초대 보기 | 그 그룹의 멤버 |
| 공개 범위 바꾸기, 나가기 | 본인 |
| 초대 취소 | 그 링크를 만든 멤버와 그룹장. 다른 멤버는 403 `FORBIDDEN` |
| 초대 미리 보기 | 누구나(로그인하지 않아도). 토큰을 아는 사람 |
| 초대 수락 | 로그인한 사람(초대 링크를 가진 사람) |

그룹 공고의 권한은 공고 문서 5.1절에 있다.

## 6. 화면에 없지만 있어야 하는 것

| # | 로직 | 없으면 생기는 일 | 이 초안의 처리 | 남은 것 |
|---|---|---|---|---|
| 1 | 그룹이 생기는 길 | 화면에 그룹이 하나도 없다 | 그룹 만들기, 초대 링크, 수락 API와 테이블 | 초대 방식은 G1. 시안이 있다(화면·API 대응 문서 2.3절) |
| 2 | 멤버 확인 | 남의 그룹 공고와 댓글이 읽힌다 | 그룹 API 전부가 멤버인지 먼저 본다 | |
| 3 | 열린 공고 수 | 헤더의 "공고 N"이 목록과 다르다 | 내린 공고와 마감된 공고를 뺀 수를 서버가 센다. 마감의 기준은 공고 문서 5.4절 | |
| 4 | 나가기와 탈퇴 | 나간 사람의 관심이 계속 보인다. 탈퇴한 사람이 쓴 댓글에서 오류가 난다 | 관심은 DB가 지운다. 올린 사람과 댓글 쓴 사람은 빈 값이 될 수 있다(공고 문서 8절) | 그룹장이 없어지는 경우는 9절 |

## 7. 화면과 API

| 화면 | 쓰는 API |
|---|---|
| 헤더(그룹 전환, 내 계정) | `GET /api/me`, `GET /api/groups` |
| 내 그룹 | `GET /api/groups`(가장 가까운 마감 포함). 그룹 만들기는 `POST /api/groups` |
| 멤버·초대 관리 | `GET /api/groups`(들어온 날 포함). 공개 범위는 `PUT …/me/disclosure`, 초대 링크는 `POST …/invites`, 살아 있는 초대는 `GET …/invites`, 취소는 `DELETE …/invites/{inviteId}`, 나가기는 `DELETE …/me` |
| 그룹 초대 수락 | `GET /api/group-invites/{token}`(로그인 없이), `POST /api/group-invites/{token}/accept` |

프런트의 `api.ts` 함수와의 대응: `getMyGroups` → `GET /api/groups`, `getInvite` → `GET /api/group-invites/{token}`, `acceptInvite` → `POST /api/group-invites/{token}/accept`. 화면별로 보이는 값은 화면·API 대응 문서 2.3절에 있다. 시안이 요구하던 초대 내용 조회(3.1의 1번), 살아 있는 초대 보기와 취소(3번), 멤버가 들어온 날(4번), 그룹별 가장 가까운 마감(5번)은 2026-11-15에 4절로 들어왔다. 로그인한 뒤 초대로 돌아오기(2번)는 프런트가 맡는다.

## 8. 프런트와 맞출 것

1. id가 숫자다(구조 문서 5절). 프런트 타입의 `id: string`을 바꾸거나 서버가 문자열로 보낸다.
2. (2026-11-13 서버를 만들며 더함) `GET /api/groups`의 `leaderId`가 `null`일 수 있다(그룹장이 계정을 지운 그룹, 9절). 지금 타입은 `string`이다.
3. (같은 날) 그룹 목록은 내가 들어간 순서다. 첫 화면이 가는 "내 첫 그룹"은 처음 들어간 그룹이다.
4. (같은 날) 초대 링크는 `<프런트 주소>/invites/<토큰>`이다. 프런트에 이 화면을 만들고, 로그인한 뒤 `POST /api/group-invites/{token}/accept`를 부르면 된다.
5. (같은 날) 그룹 만들기·공개 범위 바꾸기·초대 수락은 `Group` 모양을 돌려준다. 받은 값으로 화면의 그 부분만 바꾸면 된다.
6. (2026-11-15 더함) 초대 미리 보기(`GET /api/group-invites/{token}`)의 본문은 `{ groupName, mark, inviterName, memberCount }`다. 프런트의 `InviteView`에 있는 `status`와 `groupId`는 싣지 않는다. `getInvite`가 200이면 `"open"`, 404 `INVITE_NOT_FOUND`와 410 `INVITE_EXPIRED`면 `"expired"`로 바꾸면 된다(가짜 서버도 둘을 같게 본다). 들어간 그룹의 id는 수락 응답에 있다.
7. (같은 날) 미리 보기의 `inviterName`이 `null`일 수 있다(만든 사람이 계정을 지운 링크). 지금 타입은 `string`이다.
8. (같은 날) `GET /api/groups`의 `members[].joinedAt`과 `nearestDeadline`은 프런트 타입(`GroupMember`, `Group`)의 이름과 모양 그대로다. 두 곳의 `shortcut:` 표시를 걷으면 된다.
9. (같은 날) 살아 있는 초대 목록과 취소는 프런트에 아직 타입과 화면이 없다. 목록의 한 줄은 `{ id, createdBy: { id, name } | null, createdAt, expiresAt }`이고, 시각은 `+09:00`이 붙은 ISO 8601이다. 취소는 그룹장에게는 모든 줄에, 다른 멤버에게는 `createdBy.id`가 자기인 줄에만 보이면 된다.
10. (같은 날, 고칠 것) 서버가 만드는 초대 링크는 `<프런트 주소>/invites/<토큰>`인데 프런트의 초대 화면은 `/invite/:token`(`shared/lib/paths.ts`)이다. 어느 쪽을 바꿀지 정해야 한다. 이번 작업에서는 고치지 않았다.

## 9. 새로 생긴 결정

| 항목 | 내용 | 선택지 |
|---|---|---|
| 그룹장이 없어질 때 | 그룹장은 나갈 수 없게 했지만 계정을 지우면 그룹장 없는 그룹이 남는다 | 넘기기 API를 둔다 / 가장 먼저 들어온 멤버가 이어받는다 / 탈퇴하기 전에 넘기게 막는다 |
| 초대 | 누가 만드는지, 며칠 가는지, 인원 제한이 있는지 | G1의 값(멤버 누구나, 7일, 제한 없음) / 그룹장만 |

시안에서 새로 나온 결정(선택지 포함)은 화면·API 대응 문서 3.1절에 있다.
