## 3. 테이블

| 테이블 | 내용 |
|---|---|
| `groups` | 그룹. 이름, 표시 글자 |
| `group_members` | 그룹 × 사용자. 역할(그룹장·멤버), 이 그룹에 정한 공개 범위 |
| `group_invites` | 초대 링크의 토큰(해시로 보관), 만료 시각 |

### 3.1 생성 SQL

`V3__groups.sql`의 앞부분이다. V3 한 파일에 그룹과 그룹 공고 테이블이 함께 있고, 뒷부분은 공고 문서 3.1에 있다. 아래는 마이그레이션 파일과 글자가 같다. 고칠 일이 생기면 마이그레이션 파일이 원본이다.

```sql
-- 리드미 V3: 그룹 · 그룹 공고
set search_path to readme;

-- ── 그룹 ─────────────────────────────────────────────────────────────
create table groups (
  id         bigint generated always as identity primary key,
  name       varchar(50) not null,
  mark       varchar(4)  not null,               -- 헤더 동그라미 안의 글자. 비워 보내면 서버가 이름 첫 글자를 넣는다
  created_by bigint references users(id) on delete set null,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create table group_members (
  group_id   bigint      not null references groups(id) on delete cascade,
  user_id    bigint      not null references users(id)  on delete cascade,
  role       varchar(10) not null default 'MEMBER'  check (role in ('LEADER', 'MEMBER')),
  disclosure varchar(10) not null default 'APPLIED' check (disclosure in ('INTEREST', 'APPLIED', 'PROGRESS')),
  joined_at  timestamptz not null default now(),
  primary key (group_id, user_id)
);
create unique index group_members_leader_key on group_members (group_id) where role = 'LEADER';  -- 그룹장은 한 명
create index group_members_user_idx on group_members (user_id);

create table group_invites (
  id         bigint generated always as identity primary key,
  group_id   bigint      not null references groups(id) on delete cascade,
  token_hash char(64)    not null unique,        -- 토큰 원문은 초대 링크에만 있다. DB에는 SHA-256
  created_by bigint references users(id) on delete set null,
  expires_at timestamptz not null,
  revoked_at timestamptz,
  created_at timestamptz not null default now()
);
create index group_invites_group_idx on group_invites (group_id);
```

### 3.2 설계 이유

- **그룹장은 부분 유일 인덱스로 한 명만 둔다.** 역할은 계정이 아니라 그룹 가입 정보에 있다(정리 문서 7절의 제안).
- **`groups`라는 이름.** PostgreSQL에서는 따옴표 없이 테이블 이름으로 쓸 수 있다(실행해 확인했다).
- **그룹의 멤버만 그룹 안의 것을 본다.** 다른 기능은 `group/GroupAccess.requireMember`로 멤버인지 먼저 본다(G3).

### 3.3 확인한 것

임시 PostgreSQL 16.15에 V1, V2, V3를 차례로 실행하고 아래를 SQL로 돌려 봤다. V3는 공고 테이블과 함께 확인했다(공고 문서 3.3).

| 확인 | 결과 |
|---|---|
| V1·V2 위에 V3 적용, 새 테이블 9개 생성 | 통과 |
| 내 그룹 목록: 그룹장, 내 공개 범위, 멤버, 열린 공고 수(내린 공고와 마감된 공고 제외) | 통과 |
| 그룹장 두 명, 정해지지 않은 공개 범위 | 모두 막힘 |
| 그룹 나가기: 그 그룹의 관심은 지워지고 내 공고와 댓글은 남는다 | 통과 |
| 계정 삭제: 멤버·관심·내 공고는 지워지고, 올린 공고와 댓글은 올린 사람·쓴 사람만 빈다 | 통과. 그룹장이 탈퇴하면 그룹장 없는 그룹이 남는다(9절) |
| 그룹 삭제: 그룹 공고·관심·댓글은 지워지고 공고 본체와 내 공고는 남는다 | 통과 |

2026-11-13 서버에서 더 확인한 것: V3 를 이 절의 SQL 그대로 `V3__groups.sql`로 넣어 Flyway 가 PostgreSQL 16 에 적용했고, 복합 키 테이블(`user_postings`, `group_post_interests`)의 JPA 매핑이 `ddl-auto: validate`를 통과했다. 목록 쿼리의 속도는 아직 재지 않았다.

## 4. API

공통 규칙과 공통 오류 코드는 구조 문서 5절에 있다.

| 메서드·주소 | 하는 일 | 비고 |
|---|---|---|
| `GET /api/groups` | 내가 속한 그룹들 | 화면의 `Group` 모양: 멤버 목록, 그룹장, 열린 공고 수, 내 공개 범위 |
| `POST /api/groups` | 그룹 만들기 | `name`, `mark`(비우면 이름 첫 글자). 만든 사람이 그룹장이 된다 |
| `PUT /api/groups/{groupId}/me/disclosure` | 이 그룹에 보일 내 공개 범위 바꾸기 | `interest` · `applied` · `progress` |
| `DELETE /api/groups/{groupId}/me` | 그룹 나가기 | 그룹장이면 409 `LEADER_CANNOT_LEAVE`(G2) |
| `POST /api/groups/{groupId}/invites` | 초대 링크 만들기 | 응답: 링크, 만료 시각 |
| `POST /api/group-invites/{token}/accept` | 초대 수락 | 이미 멤버면 그대로 성공. 만료·취소된 토큰은 410 `INVITE_EXPIRED` |

만들면서 정한 것(2026-11-13). 초안이 정하지 않은 빈칸이다.

- 그룹 만들기는 201 이고, 만든 그룹을 `GET /api/groups`의 한 항목 모양으로 돌려준다. 이름은 앞뒤 공백을 지운다. 표시 글자의 "이름 첫 글자"는 첫 유니코드 글자다.
- 공개 범위 바꾸기는 바뀐 그룹(같은 모양)을 돌려준다. 나가기는 204 다.
- 초대 링크 만들기는 201 과 `{ "link": "<프런트 주소>/invites/<토큰>", "expiresAt": "2026-11-20T00:30:00+09:00" }`이다. 만료 시각은 초 단위다. 프런트에는 아직 `/invites/:token` 화면이 없다.
- 초대 수락은 들어간 그룹(같은 모양)을 돌려준다. 없는 토큰은 404 `INVITE_NOT_FOUND`다. 이미 멤버면 링크가 만료·취소되었어도 성공으로 본다. 로그인한 사람만 수락한다(로그인 없이 여는 주소는 더하지 않았다).

2026-11-15에 정한 것(9절의 "그룹장이 없어질 때"):

- **그룹장이 탈퇴하면 넘긴다**: 그룹장이 탈퇴하면(`POST /api/me/withdraw`, 로그인 문서 4.1) 그룹장인 그룹마다 그룹장 말고 가장 먼저 들어온 멤버가 그룹장이 된다. 들어온 시각이 같으면 사용자 id가 작은 사람이다. 혼자인 그룹은 지운다. 그 그룹의 그룹 공고·관심·댓글·초대는 함께 지워지고, 공고 본체와 내 공고는 남는다(3.3의 그룹 삭제).
- 넘기는 일은 `group/LeaderHandover`가 한다. 탈퇴를 맡은 `auth`가 계정을 지우기 바로 전에 내는 이벤트(`auth/AccountDeleting`)를 같은 트랜잭션에서 받는다. 넘기다 실패하면 탈퇴도 되돌려진다(구조 문서 3절).
- 그룹장은 그룹에 한 명뿐이라(부분 유일 인덱스) 탈퇴하는 그룹장의 멤버 행을 먼저 지우고 이어받을 사람을 올린다.
- 탈퇴 화면의 미리 보기(`GET /api/me/withdrawal`)가 그룹마다 이어받을 사람을 같은 순서로 보여 준다.
- 넘기는 사이 마지막 멤버가 들어오거나 나가는 경합에서는 그룹장 없는 그룹이 남을 수 있다. 멤버가 남은 그룹은 지우지 않는다(`LeaderHandover`의 shortcut 주석).
- 그룹장이 직접 넘기는 API는 만들지 않았다.

### 4.1 오류 코드

| code | HTTP | 언제 |
|---|---|---|
| `GROUP_NOT_FOUND` | 404 | 그룹이 없거나 멤버가 아니다(G3) |
| `LEADER_CANNOT_LEAVE` | 409 | 그룹장이 나가려 했다(G2) |
| `INVITE_NOT_FOUND` | 404 | 새로. 그런 초대 링크가 없다(주소가 잘렸거나 잘못 옮겨졌다) |
| `INVITE_EXPIRED` | 410 | 만료되었거나 취소된 초대 링크 |

### 4.2 응답 모양

`GET /api/groups`의 한 항목. 그룹 만들기, 공개 범위 바꾸기, 초대 수락도 이 모양을 돌려준다.

```json
{
  "id": 1,
  "name": "백엔드 스터디",
  "mark": "백",
  "members": [{ "id": 1, "name": "다온" }, { "id": 2, "name": "가람" }],
  "leaderId": 2,
  "openPostCount": 6,
  "myDisclosure": "applied"
}
```

## 5. 권한

그룹 API는 모두 로그인한 그 그룹의 멤버만 부를 수 있다. 멤버가 아니거나 그룹이 없으면 404 `GROUP_NOT_FOUND`를 준다(G3).

| 동작 | 할 수 있는 사람 |
|---|---|
| 보기, 초대 링크 만들기 | 그 그룹의 멤버 |
| 공개 범위 바꾸기, 나가기 | 본인 |
| 초대 수락 | 로그인한 사람(초대 링크를 가진 사람) |

그룹 공고의 권한은 공고 문서 5.1절에 있다.

## 7. 화면과 API

| 화면 | 쓰는 API |
|---|---|
| 헤더(그룹 전환, 내 계정) | `GET /api/me`, `GET /api/groups` |
| 내 그룹 | `GET /api/groups`. 그룹 만들기는 `POST /api/groups` |
| 멤버·초대 관리 | `GET /api/groups`. 공개 범위는 `PUT …/me/disclosure`, 초대 링크는 `POST …/invites`, 나가기는 `DELETE …/me` |
| 그룹 초대 수락 | `POST /api/group-invites/{token}/accept` |

프런트의 `api.ts` 함수와의 대응: `getMyGroups` → `GET /api/groups`. 화면별로 보이는 값은 화면·API 대응 문서 2.3절에 있다. 시안이 요구하는데 이 문서에 없는 것: 초대 내용 조회(3절 1번), 로그인한 뒤 초대로 돌아오기(2번), 살아 있는 초대 보기와 취소(3번), 멤버가 들어온 날(4번), 그룹별 가장 가까운 마감(5번).

## 8. 프런트와 맞출 것

1. id가 숫자다(구조 문서 5절). 프런트 타입의 `id: string`을 바꾸거나 서버가 문자열로 보낸다.
2. (2026-11-13 서버를 만들며 더함) `GET /api/groups`의 `leaderId`가 `null`일 수 있다(그룹장이 계정을 지운 그룹, 9절). 지금 타입은 `string`이다. 2026-11-15부터는 그룹장이 탈퇴하면 넘기므로(4절) 드문 경합 말고는 이런 그룹이 생기지 않는다.
3. (같은 날) 그룹 목록은 내가 들어간 순서다. 첫 화면이 가는 "내 첫 그룹"은 처음 들어간 그룹이다.
4. (같은 날) 초대 링크는 `<프런트 주소>/invites/<토큰>`이다. 프런트에 이 화면을 만들고, 로그인한 뒤 `POST /api/group-invites/{token}/accept`를 부르면 된다.
5. (같은 날) 그룹 만들기·공개 범위 바꾸기·초대 수락은 `Group` 모양을 돌려준다. 받은 값으로 화면의 그 부분만 바꾸면 된다.

## 9. 새로 생긴 결정

| 항목 | 내용 | 선택지 |
|---|---|---|
| 그룹장이 없어질 때 | 그룹장은 나갈 수 없게 했지만 계정을 지우면 그룹장 없는 그룹이 남는다 | 넘기기 API를 둔다 / 가장 먼저 들어온 멤버가 이어받는다 / 탈퇴하기 전에 넘기게 막는다 |
| 초대 | 누가 만드는지, 며칠 가는지, 인원 제한이 있는지 | G1의 값(멤버 누구나, 7일, 제한 없음) / 그룹장만 |

시안에서 새로 나온 결정(선택지 포함)은 화면·API 대응 문서 3.1절에 있다.
